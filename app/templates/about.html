A configurable platform for training, validating and applying urban waterlogging classifiers, starting with {{ city.name }}.

Project overview

Upload a labelled history of waterlogging events, validate it, train and compare scikit-learn classifiers, then apply a validated model to single locations or CSV batches. Live Open-Meteo weather supplies rainfall and elevation inputs, always with its source and kind shown.

Initial region: Mumbai Metropolitan Region, Maharashtra. Other cities are added through configuration and compatible CSV uploads.

Problem statement

Street-level waterlogging depends on rainfall intensity and accumulation, ground elevation and slope, drainage capacity, tides and local conditions. Rainfall alone does not determine whether water accumulates, so rainfall is treated as one input and verified event labels are required to learn the rest.

Workflow

  1. Upload CSV
  2. Explore & validate
  3. Train & evaluate
  4. Activate a validated model
  5. Predict (single / batch)
  6. History & export

System architecture

Web / API
FastAPI (Python), Jinja2 pages, vanilla JavaScript
Services
Validation, features, training, prediction, explainability, weather (independent of ML)
ML
scikit-learn pipelines, pandas, NumPy, joblib
Database
SQLAlchemy + Alembic; SQLite locally, PostgreSQL in production
Artifacts
Storage interface (local volume today); models are hash-checked on load
Weather
Open-Meteo Forecast, Historical, Elevation and Geocoding APIs, called from the server only

Machine-learning methodology

Logistic Regression (baseline), Random Forest and HistGradientBoosting are trained on chronological or location-grouped splits with preprocessing fitted on training data only. Candidates are compared on validation PR-AUC against a prevalence baseline, probabilities are sigmoid-calibrated on validation data, and the test split is used once.

Activation gates: verified-label attestation and provenance, time/space-aware split, enough distinct locations, test PR-AUC above prevalence by a margin, sufficient positives per split. Only models passing every gate can be activated.

Data sources & attribution

  • Open-Meteo: current conditions, precipitation (model analysis, reanalysis, forecast), elevation, geocoding. Not station observations; check current terms and attribution before production use.
  • IMD / India-WRIS rainfall and incident labels: candidate sources, not yet verified or used. See docs/DATA_SOURCES.md.

Responsible use & limitations

  • No verified labelled waterlogging dataset and no validated trained model are bundled. Predictions stay unavailable until you supply data and a model passes validation.
  • Weather values do not prove street-level waterlogging.
  • A model applies only to its training period and area; out-of-region points are flagged.
  • “Validated” means it passed the gates on the supplied data; it is not a safety guarantee.
